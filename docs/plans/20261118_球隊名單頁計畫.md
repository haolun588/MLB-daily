# 修改計畫：球隊名單頁（2026-11-18）

> 狀態：**實作完成，待 GitHub 實測**。依 `docs/dev_rules.md`，流程是先做靜態設計稿、經使用者核准後才實作，一次只做一個模組。

## 一、需求

網站新增一個頁面：
- 點選隊徽後，顯示該隊目前的大聯盟名單。
- 球員依守備位置分組。
- 每位球員後面列出本季數據。

## 二、已確定的決策（2026-11-18 與使用者討論）

### 名單類型
- 賽季中顯示 **26 人現役名單**（`rosterType=active`），休賽季自動改顯示 **40 人名單**（`rosterType=40Man`）。
- 判斷賽季：依 `GET /api/v1/seasons/{year}?sportId=1` 的 `regularSeasonStartDate` 至 `postSeasonEndDate`，期間內視為賽季中。
- 不以名單人數判斷，因為 2026-11-18 實測休賽季 `rosterType=active` 仍回傳 33 人。

### 守備位置分組（2026-11-18 使用者調整）
- 改為三張表：**SP 先發投手、RP 後援投手、野手**（取消原 C、1B、…、UTIL 各自分組）。
- 投手區分 SP 與 RP：API 只把投手標為 `P`，以本季 `gamesStarted / gamesPitched ≥ 0.5` 判定為 SP，其餘（含本季無出賽紀錄者）為 RP。
- 野手全部合併一張表，每人顯示「守位」欄（API 位置代號：C、1B、2B、3B、SS、LF、CF、RF、DH；`IF`、`OF`、`UT` 等顯示原代號；二刀流顯示 `TWP`）。
- 二刀流（`TWP`）：打擊數據列在野手表（守位 TWP），投球數據依上述 SP/RP 規則放進對應投手表，兩處名字下方皆標「二刀流」。
- JSON 表示：單一球員物件含 `hitting` 與 `pitching`，`group` 為 `"POS"`，另加 `pitchingGroup: "SP"|"RP"`；一般野手 `group` 為 `"POS"`、投手為 `"SP"`／`"RP"`，`pos` 保留 API 原始代號。

### 數據欄位
資料為**當季**（休賽季為剛結束的球季）；交易來的球員為全季合計。

| 分組 | 欄位 |
|---|---|
| 野手 | 守位、G、PA、AVG、OBP、SLG、HR、SB、BB%、K%、wRC+、WAR（2026-11-18 起新增守位欄，置於球員名前） |
| 先發投手（SP） | G、GS、IP、W-L、ERA、WHIP、SO、K/9、FIP、WAR |
| 後援投手（RP） | G、IP、SV、HLD、ERA、WHIP、SO、K/9、FIP |

- 欄位計算：
  - BB% = BB ÷ PA，K% = SO ÷ PA，皆由程式計算。
  - K/9 直接使用 API 的 `strikeoutsPer9Inn`。
  - wRC+、WAR、FIP 來自 `sabermetrics`。
- 不列 RBI。
- 球員欄：背號、英文姓名（連到 Baseball Savant）。
- 本季無數據的球員顯示「—」。
- 不加樣本數過小的提醒。

### 互動
- 點欄位標題排序，在各表（SP、RP、野手）內各自排序，再點一次切換升冪或降冪。
- 預設排序（2026-11-18 調整）：投手依 IP 由高到低；野手依守位順序 C→1B→2B→3B→SS→LF→CF→RF→DH→其他，同守位內依 PA 由高到低。無數據者排在最後。
- 守位欄可排序，依上述守位順序（非字母序）；守位以小型等寬標籤呈現。
- 手機版：表格可左右滑動，背號、（野手表）守位與球員名字固定在左側（sticky columns）。
- 網址帶球隊縮寫（例如 `teams.html#NYY`），可直接分享。
- 首頁、戰報頁、存檔頁加入「球隊名單」連結。

## 三、資料流程

- 每日 workflow 在產生戰報之後，額外執行 `python fetch_mlb.py --rosters`（暫定）：
  - 對 30 隊各呼叫一次：`/api/v1/teams/{id}/roster?rosterType=...&season=YYYY&hydrate=person(stats(type=[season,sabermetrics],group=[hitting,pitching],season=YYYY))`。2026-11-18 已實測，一次請求即含 season 與 sabermetrics 數據。
  - 精簡後寫入 `data/teams/{teamId}.json`，另寫一份 `data/teams/index.json`，內含更新時間、名單類型與 30 隊清單。
- 名單更新失敗**不影響**當日戰報與通知：
  - 該步驟獨立執行；
  - 單隊失敗時保留前一天的檔案；
  - 全數失敗時 job 印出警告。
- `data/` 與 `teams.html` 部署到 gh-pages。

## 五、待確認／風險

- 兩隊之間交易的球員，本季數據為全季合計，不會只算在新球隊的部分。
- `sabermetrics` 對樣本極少的球員可能缺欄位，一律顯示「—」。
- 資料量：每隊精簡後預估 10–20 KB，30 隊合計約 0.5 MB，只在選到該隊時才載入。
