# 季後賽對戰樹設計（2026-11-19，使用者已核准）

規格來源：`docs/plans/20261118_新功能規劃.md` 第一節第 6 項。本文件補上 API 實測結果、實作方式與使用者決定。

## 一、API 實測結果

端點：`https://statsapi.mlb.com/api/v1/schedule/postseason/series?season={season}&sportId=1`（2026-11-19 實測可用，一次請求就能取得整屆資料）。

| 欄位 | 內容 |
| --- | --- |
| `series[].series.id` | `F_1`～`F_4`（外卡）、`D_1`～`D_4`（分區）、`L_1`～`L_2`（聯盟冠軍賽）、`W_1`（世界大賽） |
| `series[].games[]` | 該系列每一場比賽（已打完與排定的場次都有） |
| `games[].seriesDescription` | `AL Wild Card Series`、`NL Division Series`、`AL Championship Series`、`World Series`，前綴 `AL`／`NL` 可判斷聯盟 |
| `games[].description` | 例如 `ALDS 'B' Game 5`，含組別字母 |
| `games[].gamesInSeries` | 3／5／7，晉級所需勝場為 `gamesInSeries // 2 + 1` |
| `games[].teams.{away,home}` | `team.id`、`team.name`、`score`、`isWinner`、`leagueRecord`（該系列賽累計戰績） |
| `games[].status.codedGameState` | `F` 為已完賽，`D` 為延賽，其餘為未開打或進行中 |

2026 季後賽實測結果（用來驗證頁面內容）：

- 美聯外卡：白襪 2–0 太空人、洋基 2–0 紅襪；國聯外卡：勇士 2–1 費城人、教士 2–0 小熊
- 美聯分區：光芒 3–0 洋基、守護者 3–2 白襪；國聯分區：釀酒人 3–1 教士、道奇 3–1 勇士
- 美聯冠軍賽：光芒 4–2 守護者；國聯冠軍賽：釀酒人 4–0 道奇
- 世界大賽：釀酒人 4–1 光芒

實測注意事項：

1. **延賽會多出一筆資料**：美聯冠軍賽第 4 戰因雨延賽，`games` 裡同一個 `gamePk` 出現兩次，一次是 `Postponed`（`codedGameState` 為 `D`，但 `abstractGameState` 仍是 `Final`，而且沒有比分）。計算勝場時只能算 `codedGameState == "F"` 的場次，並以 `gamePk` 去重，不能只看 `abstractGameState`。
2. **沒有種子序欄位**：API 不提供種子序，因此首輪輪空的隊伍以「出現在分區系列賽、但不是外卡勝隊」判斷。
3. **組別字母不等於路線**：外卡 'A' 的勝隊（白襪）進的是分區 'B'。外卡與分區系列賽的對應要用隊伍 ID 比對（外卡任一隊出現在哪一組分區系列賽，就接到那一組），不能用字母或 ID 編號對應。
4. 季後賽進行中，尚未產生對手的系列賽可能沒有資料或隊伍不完整；這部分只能用 fixture 模擬，2026 年資料已打完，無法實測。

## 二、建議做法

### 1. 模組與輸出

- 新增 `mlb_daily/playoffs.py`，層級與 `leaders` 相同（可 import `config`、`timeutil`、`net`、`htmlutil`、`storage`，不得 import 上層）。
- `config.py` 新增 `POSTSEASON_SERIES_URL`、`PLAYOFFS_PATH = "data/playoffs.json"`、`PLAYOFFS_PAGE_PATH = "playoffs.html"`。
- 主要函式：
  - `fetch_postseason(season)`：抓取原始資料，失敗回傳 `None`。
  - `parse_postseason(data)`：轉成結構化資料（純函式，方便測試）。
  - `generate_playoffs(today, now=None)`：決定要顯示哪一屆，寫入 `data/playoffs.json` 與根目錄 `playoffs.html`。抓取失敗時回傳 False，並保留舊檔不覆寫。
  - `render_playoffs_page(data)` 與 `render_playoffs_card(data)`。
- 新增模板 `templates/playoffs.html`，結構仿 `templates/leaders.html`，導覽列加入「季後賽」。必須確認這個模板有被 git 追蹤（`.gitignore` 只忽略根目錄的 `/playoffs.html`）。
- CLI 新增 `--playoffs` 模式，與 `--leaders` 一樣不可和其他模式併用；成功後若有 `reports/metadata.json` 就呼叫 `index_page.refresh_index_page()`。

### 2. 結構化資料（`data/playoffs.json`）

```json
{
  "season": 2026,
  "status": "完成 | 進行中",
  "champion": {"id": 158, "name": "..."},
  "rounds": {
    "AL": {"F": [...], "D": [...], "L": [...]},
    "NL": {"F": [...], "D": [...], "L": [...]},
    "WS": [...]
  },
  "updatedAt": "..."
}
```

每組系列賽包含：`id`、`label`（例如「美聯分區 B」）、兩隊（`id`、名稱、勝場）、`winsNeeded`、`state`（`未開打`／`進行中`／`已結束`）、`winnerId`（尚未分出勝負時為 null）。

勝場計算：只算 `codedGameState == "F"` 的場次，以 `gamePk` 去重，再依 `isWinner` 累加。某隊勝場達到 `winsNeeded` 即晉級。（實作調整見第四節）

### 3. 顯示哪一屆

- 先抓今年的資料；如果今年的季後賽還沒有任何一場完賽或進行中的比賽，就改抓去年的資料。
- 頁面標題：季後賽進行中顯示「YYYY 季後賽・截至 M/D」；打完後顯示「YYYY 季後賽結果」。
- 因此現在（2026-11）到 2027 年季後賽開打前，頁面都顯示「2026 季後賽結果」。

### 4. 首頁小卡

- 位置：首頁側欄，排行榜小卡下方，底部連結「完整對戰樹 →」。
- 季後賽進行中：列出目前這一輪各系列賽的比數，例如「光芒 2–1 守護者」。
- 季後賽結束後：顯示「2026 世界大賽冠軍：釀酒人（4–1 勝光芒）」。
- 顯示期間：從季後賽開打到隔年開季前（用 `rosters.resolve_roster_context` 判斷）；例行賽期間隱藏，只保留導覽列連結。

### 5. 版面

- 桌面版（`min-width: 1024px`）：左右對稱的 7 欄格線，依序為美聯外卡、美聯分區、美聯冠軍賽、世界大賽、國聯冠軍賽、國聯分區、國聯外卡。每組分區系列賽與餵給它的外卡系列賽放在同一列，輪空隊伍那一側標示「首輪輪空」。用 CSS grid 排版，連接線用框線實作，不使用 JavaScript。（實作調整見第四節）
- 手機與平板（`< 1024px`）：依輪次由上而下排列卡片，順序為世界大賽、聯盟冠軍賽、分區系列賽、外卡系列賽；同一輪內美聯在前、國聯在後，不需要橫向捲動。
- 系列賽卡片：兩隊各占一列，顯示隊名與勝場；勝隊粗體並加上晉級標記，敗隊淡化；進行中的系列賽標示「進行中」。（實作調整見第四節）
- 隊名使用專案既有的中文隊名對照；查不到對照或資料尚未產生時顯示「待定」。所有外部字串一律經過 `esc()`。

### 6. Workflow

- `daily_report.yml`：在「Restore history from gh-pages」步驟加上還原 `data/playoffs.json`（取不到只發 warning）；在 Update Stat Leaders 之後新增「Update Postseason Bracket」步驟，執行 `python fetch_mlb.py --playoffs`，並設定 `continue-on-error: true`。
- 每天都會執行（只需一次 API 請求），因此季後賽期間會每天更新。
- 根目錄的 `playoffs.html` 會由既有的 `publish_dir: ./` 一起部署，不需要額外複製。

### 7. 測試（不連網）

- 新增 fixture `tests/fixtures/postseason_series_2026.json`，內容為 2026 年實際回應（可精簡無關欄位，但必須保留延賽那一筆）。
- 另以程式碼產生「進行中」的 fixture：分區系列賽打到一半、聯盟冠軍賽與世界大賽尚無資料。
- 新增 `tests/test_playoffs.py`，繼承 `MlbTestBase`，patch `mlb_daily.net.fetch_json`，測試涵蓋：
  - 勝場計算與延賽去重：美聯冠軍賽應為 4–2，不能是 4–3 或其他數字。
  - 外卡與分區的對應：白襪接到分區 'B'、洋基接到分區 'A'，並正確判斷輪空隊伍。
  - 冠軍判斷。
  - 今年沒有資料時改用去年。
  - 抓取失敗時不覆寫舊檔。
  - 頁面與小卡的 HTML：跳脫、標題、「待定」。
  - CLI 參數。
  - 靜態檢查：workflow 有新步驟、導覽列有連結、`.gitignore` 規則、`git ls-files templates/playoffs.html` 確認模板有被追蹤，以及分層規則。

### 8. 文件

更新 `docs/architecture.md`（模組表與檔案結構樹，順便補上排行榜漏列的項目）、`docs/progress.md`、`README.md`（若有功能清單），並新增 `docs/dev_logs/20261119_新增季後賽對戰樹.md`。

## 三、使用者決定（2026-11-19）

1. 放置位置：獨立頁 `playoffs.html`，另加首頁小卡。
2. 非季後賽期間：顯示上一屆結果，標題為「YYYY 季後賽結果」。
3. 手機版：依輪次直向堆疊卡片，不使用橫向捲動。

## 四、實作備註

- **JSON 多出的欄位**：除了設計的 `season`、`status`、`champion`、`rounds`、`updatedAt`，另有 `schema`（與排行榜一致，讀檔時版本不符就忽略）、`asOf`（資料截至的台北昨日，進行中標題「截至 M/D」用）；外卡系列賽多 `feedsInto`（接到哪一組分區系列賽，以隊伍 ID 比對），分區系列賽多 `byeIds`（首輪輪空隊伍）。讓渲染端不必重新推算。
- **小卡顯示期間**：不另外判斷月份，改以 `data/playoffs.json` 的 `season` 是否等於 `resolve_roster_context` 的數據賽季。結果：10 月季後賽進行中（賽季為今年、資料為今年）顯示；11–12 月與隔年 1–3 月（賽季為資料年）顯示；隔年 4 月起例行賽（賽季為新的一年、資料仍是上一屆）隱藏。`_fallback_roster_context` 在 1–3 月改回傳 `year - 1`，與 `resolve_roster_context` 一致。
- **兩套 DOM**：桌面樹與手機堆疊各渲染一份，以 CSS media query 切換（不用 JS）。桌面樹內卡片很窄，因此隱藏「晉級」文字（勝隊靠粗體與顏色）與列內「首輪輪空」標籤，輪空改為卡片標頭下方小字「首輪輪空：光芒」；手機版仍保留列內標籤。世界大賽格的 class 用 `po-ws`，避免與勝場數字的 `.po-w` 撞名。
- **`"O"` 狀態**：`codedGameState` 為 `"F"` 或 `"O"`（Game Over）都視為完賽，但 `"O"` 必須該場已有布林的 `isWinner` 才計入；`"D"`（延賽）一律排除，仍以 `gamePk` 去重。
- **待定隊伍**：只有 `config`（`TEAM_NAMES_EN`／`TEAM_META`）查得到的 id 才算真實隊伍；查不到的 id 顯示「待定」，不被當成輪空隊，也不參與外卡與分區的對應。
