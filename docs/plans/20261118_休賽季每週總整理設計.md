# 休賽季每週總整理設計

> 狀態：**已核准**（2026-11-18，使用者已決定第 11 節三項；依 `docs/dev_rules.md` 第 1、8 條可開始實作）
> 來源：`docs/plans/20261118_新功能規劃.md` 第二節

## 1. 目標

休賽季每週一（台北時間）產出一份 `reports/weekly/YYYY-Www.html`，彙整上一個 ISO 週（週一至週日）的人事異動與新聞。資料全部來自每日產報時存下的 `data/daily/YYYY-MM-DD.json`，**不重抓 API、不重新送 Gemini 翻譯**。首頁、存檔頁、Discord 都附上週報連結。

## 2. 前置：每日資料快照 `data/daily/YYYY-MM-DD.json`

### 2.1 寫入時機

`report.generate_report`（有賽事）與 `report.generate_offseason_report`（無賽事）在翻譯完成、寫出 HTML 後，都呼叫新的 `storage.write_daily_snapshot(date_str, payload)`（用既有 `write_json_atomic`）。快照失敗只印警告，不影響戰報。

### 2.2 格式（`schema: 1`）

```json
{
  "schema": 1,
  "date": "2026-11-18",
  "has_games": false,
  "transactions": [
    {"type_code": "TR", "date": "2026-11-18", "description": "...", "description_zh": "...",
     "person_id": 123, "person_name": "...", "persons": [{"id": 123, "name": "..."}],
     "to_team_id": 137, "from_team_id": 120}
  ],
  "news": [
    {"title": "...", "title_zh": "...", "link": "...", "published": "2026-11-18T09:30:00+08:00",
     "image": "...", "summary": "..."}
  ]
}
```

- `transactions`：經 `filter_major_league_transactions` 篩過、已翻譯的大聯盟異動（與戰報顯示的同一批）。
- `news`：當天戰報**實際顯示並翻譯過**的新聞（最多 12 則），`published` 存 ISO 字串。
- 不另存台日韓比對結果，週報產生時用當下的 `settings/watchlist.json` 重新比對（`players_in_transaction`、`players_in_text`）。

### 2.3 部署與保存（已查 workflow）

- `data/` 已在 `.gitignore`，**不在** `peaceiris/actions-gh-pages` 的 `exclude_assets` 內，且 `keep_files: true`，所以每天寫出的 `data/daily/*.json` 會隨部署累積在 gh-pages。
- 但 CI 每次都是全新 checkout，`Restore history from gh-pages` 目前只還原 `reports/metadata.json`。**需新增還原 `data/daily/` 與 `reports/weekly/index.json`**：

  ```bash
  git archive origin/gh-pages data/daily | tar -x || echo "::warning::gh-pages 尚無 data/daily"
  git show origin/gh-pages:reports/weekly/index.json > reports/weekly/index.json 2>/dev/null || rm -f reports/weekly/index.json
  ```

  用 `git archive | tar -x` 只寫工作目錄、不動 index。週報只需要最近 7 天，但目錄很小，全部還原較簡單。

## 3. 產生條件與排程

- 新增 CLI 參數 `--weekly`（可搭配 `--week 2026-W47` 手動指定週次）。
- workflow 在每日產報之後新增 `Generate Weekly Report` 步驟：`python fetch_mlb.py --weekly`。程式自行判斷：
  1. 台北時間今天是週一（手動指定 `--week` 時略過此條件）。
  2. 休賽季：沿用 `rosters.resolve_roster_context(今天)`，`rosterType != "active"` 才產生（例行賽開打到季後賽結束期間不產）。手動 `--week` 也套用此條件，加 `--force` 才略過。
  3. 讀取該週 7 天的快照（週一跑時，週日的快照剛由當天每日產報寫出）。
- 週次定義：ISO 週，檔名 `YYYY-Www`（例：`2026-W47` = 2026-11-16 ～ 2026-11-22），用 `date.isocalendar()`。
- 步驟設 `continue-on-error: true`，週報失敗不影響每日戰報部署。

## 4. 資料不足 7 天的處理（**採用方案 A**）

上線後第一個週一是 **2026-11-23**，要整理 W47（11/16～11/22），但快照從 11/18 的戰報才開始有（11/19 執行），最多只有 5 天。

| 方案 | 做法 | 優點 | 缺點 |
| --- | --- | --- | --- |
| **A（採用）** | 有 ≥1 天快照就照產，頁首標示「本週資料涵蓋 5／7 天（11/18～11/22）」 | 第一週就有內容；之後若某天產報失敗也不會整週消失 | 第一週內容不完整 |
| B | 不足 7 天就跳過，不產也不通知 | 每份週報都完整 | 第一份週報要等到 11/30；任何一天失敗整週沒有週報 |
| C | 不足的天數由一次性回補指令補抓 API 並翻譯 | 第一週也完整 | 違反「不重抓、不重新翻譯」原則，多一段只用一次的程式 |

0 天快照時一律不產、不通知。

## 5. 內容

頁首：週次、日期範圍、資料涵蓋天數、統計（異動 N 筆、交易 N 筆、簽約 N 筆）。

### 5.1 本週重點

全列：所有 `TR`、大聯盟合約的 `SFA`、延長合約。依日期新到舊，顯示 `description_zh`（無譯文退回英文原文）。不補合約金額。

### 5.2 分類整理（typeCode 已用真實資料確認）

以 `statsapi.mlb.com/api/v1/transactions` 查 2025-10-25～2025-12-20（1417 筆）與 2026-11-01～11-17 的分布：

| 分類 | 規則 | 真實資料例 |
| --- | --- | --- |
| 交易 | `TR` | traded 2B Nate Furman to Washington Nationals… |
| 自由球員簽約 | `SFA` 且描述**不含** `minor league contract` | |
| ~~小聯盟合約~~ | **已移除**（審查後使用者同意）：快照為大聯盟過濾後資料，描述含 `minor league` 者已被排除，此分類實務上永遠為空。`SFA` 含 `minor league contract` 一律不列入（防禦判斷保留） | |
| 延長合約 | 描述符合既有 `WEEKLY_TX_EXTENSION_RE`（`\bextension\b`） | 真實資料**沒有獨立 typeCode**，去年休賽季也未出現，可能常為空 |
| DFA／釋出／讓渡 | `DES`（指定讓渡）、`REL`（釋出）、`OUT`（outright 下放）。真實 API：DES／REL 只有 toTeam（指球員離開的那隊）；OUT 為 toTeam＝小聯盟、fromTeam＝大聯盟 | designated LHP… for assignment |
| 成為自由球員 | `DFA`（API 的 DFA = Declared Free Agency，**不是**指定讓渡） | RHP Ryne Stanek elected free agency |
| 40 人名單異動 | `SE`（selected 上 40 人）、`CLW`（waiver 撿人）、`R5`／`R5M`（Rule 5） | claimed RHP… off waivers |
| 不列入 | `SC`（傷兵名單等狀態變更）、`ASG`、`RTN`、`OPT`、`NUM`、`RET` 等 | `RET`（退休）若出現可之後再加 |

- **選擇權（option）**：真實資料中球團執行／拒絕選擇權**不會出現在 transactions API**，因此本版不做此分類（規劃文件提的「選擇權」改為不做，需使用者同意）。
- 分類對照表放 `config.py`（`WEEKLY_CATEGORIES`），之後要調整只改設定。
- 已有的首頁 `select_weekly_highlights` 仍保留（首頁休賽季區塊即時抓 API），兩者分開。

### 5.3 各隊動態

只列本週有異動（排除「不列入」與小聯盟合約）的球隊，每隊分「加入」（`to_team_id`）與「離開」（`from_team_id`；交易則雙方各記一次）。依異動筆數排序，第一名標「本週最忙」徽章（同數並列都標）。

### 5.4 本週新聞精選（10 則）

從 7 天快照的新聞去重（依 `link`），排序：提到台日韓追蹤球員 +2、提到本週重點異動球員 +1，同分新到舊，取 10 則。顯示 `title_zh`、來源連結、日期、圖片（沿用戰報新聞卡片樣式）。

### 5.5 台日韓標註

異動與新聞若涉及 `settings/watchlist.json` 名單球員，加上與球員專區相同的地區徽章（TW／JP／KR）；頁面另有一個「台日韓動態」小區塊彙整本週相關項目（沒有就不顯示）。

### 5.6 頁尾：下週日程

新增手動維護設定檔 `settings/offseason_calendar.json`：

```json
{"events": [{"date": "2026-12-08", "title_zh": "冬季會議開幕", "note": "選填"}]}
```

週報頁尾列出「下一週（週一至週日）」內的事件；沒有就顯示「下週無排定重要日程」。檔案格式錯誤只印警告。**初始內容請使用者提供或確認**（我不自行填日期，以免放錯）。

## 6. 輸出與連結

- 新模組 `mlb_daily/weekly.py`（層級與 `report` 同層：可用 `transactions`、`watchlist`、`htmlutil`、`storage`、`config`、`timeutil`，不 import `report`／`cli`），新模板 `templates/weekly.html`，CSS 沿用 `assets/` 既有樣式並少量新增。
- 週報索引 `reports/weekly/index.json`：`{"weeks": [{"week": "2026-W47", "start": "2026-11-16", "end": "2026-11-22", "days": 5, "tx_count": 120, "path": "reports/weekly/2026-W47.html", "generated_at": "..."}]}`。不放進 `reports/metadata.json`，避免影響既有以日期為鍵的邏輯。

- **Discord**：新增 `--notify-weekly`，週報部署且 Pages 回應 200 後發一則獨立訊息（標題、日期範圍、交易／簽約筆數、連結）。只有本次執行確實產生週報時才發（用 step output 控制）。

## 7. Workflow 變更（`.github/workflows/daily_report.yml`）

1. `Restore history from gh-pages`：加還原 `data/daily/` 與 `reports/weekly/index.json`（見 2.3）。
2. `Generate Daily Report` 之後新增 `Generate Weekly Report`（`continue-on-error: true`），成功產生時輸出 `weekly_url`。
3. 部署步驟不變（`data/`、`reports/weekly/` 本來就會部署）。
4. `Wait for GitHub Pages` 之後新增：有 `weekly_url` 時等待其 200，再 `--notify-weekly`（條件同每日通知：排程或 `inputs.notify`）。
5. `workflow_dispatch` 新增輸入 `week`（選填，例 `2026-W47`），手動補產指定週。

## 11. 已決定（2026-11-18）

4. 審查後（2026-11-18）：**使用者同意移除「小聯盟合約」分類**，原因：快照為大聯盟過濾後資料，該分類實務上永遠為空。各隊動態的方向規則同時修正：離開類（DES、DFA、REL、OUT）依 fromTeam、toTeam 順序取第一個屬於 30 隊的隊伍記為「離開」。

1. 資料不足 7 天：**採用方案 A**。有 ≥1 天快照就照產並在頁首標示涵蓋天數；0 天不產、不通知。
2. 「選擇權」分類：**同意拿掉**（API 沒有資料）。
3. `settings/offseason_calendar.json`：**先放空檔 `{"events": []}` 上線**，日程之後由使用者手動補；沒有事件時頁尾顯示「下週無排定重要日程」。
