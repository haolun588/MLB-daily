# 台灣與日韓球員專區設計（待核准）

狀態：2026-11-18 使用者已核准（名單含小聯盟球員、專區標題顯示中文名的例外、戰報無內容隱藏／首頁顯示近 7 天彙整）。

## 1. 目標

在每日戰報與首頁新增「台日韓球員專區」，追蹤固定名單上的台灣、日本、韓國球員：

- 休賽季：名單球員的人事異動、提到名單球員的新聞。
- 賽季中：再加上名單球員當日在大聯盟比賽的打擊／投球成績。
- 為之後的「每週總整理」留好「依球員標註」的介面。

## 2. 追蹤名單設定檔

路徑：`settings/watchlist.json`（納入版控；`data/` 被 `.gitignore` 忽略，不能放那裡）。

```json
{
  "players": [
    {"id": 678906, "name_zh": "鄧愷威", "name_en": "Kai-Wei Teng", "region": "TW"},
    {"id": 660271, "name_zh": "大谷翔平", "name_en": "Shohei Ohtani", "region": "JP", "aliases": ["Ohtani"]}
  ]
}
```

- `id`：MLB person id（已用 `statsapi.mlb.com/api/v1/people/search` 查證，見附錄）。
- `region`：`TW`／`JP`／`KR`，顯示為「台灣／日本／韓國」。
- `aliases`（選填）：新聞比對用的額外字串。預設只比對 `name_en` 全名；姓氏常見（Lee、Kim）的球員不加姓氏別名，以免誤判。
- 讀檔失敗或格式錯誤：印警告、視為空名單，專區不顯示，整次執行不得失敗。

## 3. 模組設計

新增 `mlb_daily/watchlist.py`，層級與 `transactions`／`news` 相同（只依賴 `config`、`htmlutil`）。`config.py` 新增 `WATCHLIST_PATH = os.path.join("settings", "watchlist.json")`。

| 函式 | 說明 |
| --- | --- |
| `load_watchlist(path=WATCHLIST_PATH)` | 回傳 `dict[int, dict]`（key 為 person id）。 |
| `players_in_transaction(tx, wl)` | 回傳該筆異動涉及的名單球員 id 清單（比對 `person_id` 與 `persons`）。**週報介面**。 |
| `players_in_text(text, wl)` | 回傳文字中提到的名單球員 id（不分大小寫、整詞比對 `name_en` 與 `aliases`）。**週報介面**。 |
| `match_transactions(raw_tx, wl)` | 從**未經大聯盟過濾**的當日異動挑出名單球員（含下放、指派小聯盟等）。 |
| `match_news(news, wl)` | 比對新聞標題與 RSS 摘要，回傳 `[(新聞, [球員 id])]`。 |
| `extract_game_lines(boxscores, wl)` | 依 `ID{personId}` 在當日各場 boxscore 找名單球員，回傳打擊／投球成績列。 |
| `build_spotlight(...)` | 組成可序列化的 dict（見第 5 節），供渲染與 metadata 使用。 |
| `render_spotlight_section(spotlight, wl)` | 戰報區塊 HTML。 |
| `render_spotlight_home(entries, wl)` | 首頁區塊 HTML。 |

其他模組的配合修改：

- `transactions.py`：拆出 `fetch_raw_transactions(date_str)`（只抓不過濾）；`fetch_daily_transactions` 改為呼叫它再過濾，行為不變。戰報流程只打一次 API，原始資料同時給大聯盟過濾與名單比對。
- `news.py`：RSS 每則多保存 `summary`（`<description>` 去 HTML 後的純文字，只用來比對，不顯示）；名單比對使用當日全部新聞，不受顯示上限 12 則限制。
- `translate.py`：名單異動的描述併入既有翻譯批次（同一描述沿用快取，不重複送翻）。
- `report.py`：`generate_report`／`generate_offseason_report` 呼叫上述函式，新增插槽 `SPOTLIGHT`，並把精簡結果寫進 metadata。
- `index_page.py`：首頁新增區塊。
- 模板：`templates/report.html` 在 `SUMMARY` 之後、`NEWS` 之前加 `<!--SLOT:SPOTLIGHT-->`；`templates/index.html` 在 `LATEST` 之後加 `<!--SLOT:SPOTLIGHT-->`。

## 4. 顯示

戰報區塊標題「台日韓球員動態」，依球員分組（台灣 → 日本 → 韓國，再依名單順序）：

```
鄧愷威　台灣・太空人
  ・人事異動：太空人將 Kai-Wei Teng 下放至 3A。
  ・新聞：〈……〉（連結）
大谷翔平　日本・道奇
  ・打擊 4 打數 2 安打、1 全壘打、2 打點
  ・投球 6.0 局、3 安打、1 失分、8 三振
```

- 分組標題用設定檔的中文名，這是「球員姓名保留英文」規則的**例外，只限本區塊**；異動與新聞內文仍依原規則保留英文姓名。
- 一則新聞提到多位名單球員時，放在第一位，其餘球員顯示「（同上則新聞）」不重複列出全文。
- 打擊列只在有打席（`plateAppearances` > 0 或 `atBats` > 0）時顯示；投球列只在有投球局數時顯示。二刀流兩列都顯示。只有守備或代跑出場的不顯示。
- 所有外部字串經 `esc()`；球員名連結沿用 Savant 連結。

**實作時的實際決定**

- 「同上」：一筆異動或一則新聞涉及多位名單球員時，只存一次（歸第一位），其餘球員的分組顯示「人事異動：（同上則異動）」或「新聞：（同上則新聞）」；metadata 以 `also_player_ids` 記錄。
- 投球列顯示條件放寬為：有投球局數、`battersFaced` > 0 或 `numberOfPitches` > 0 任一成立（0 局失分也要顯示，如「0.0 局、2 安打、3 失分」）。
- 打擊列另顯示二壘安打、三壘安打、盜壘、保送（0 省略）。
- 分組標題球隊：優先取 boxscore 的球隊；沒有則由該球員異動的 `to_team_id`、`from_team_id` 推算（優先 to，只取 30 隊之一）；都沒有只顯示地區。球隊用中文簡稱（如「太空人」）。
- `load_watchlist(path=None)` 於呼叫時才取 `WATCHLIST_PATH`；名單別名新增 `Kai Wei Teng`、`Jung-hoo Lee`。
- 首頁「近 7 天」為最新戰報日期往回共 7 個日曆日（含最新日）。

**沒有內容時的處理（設計決定）**

- 戰報：整區隱藏（不輸出空區塊）。理由：多數日子名單球員沒動態，每天一個「今日無」會變成噪音。
- 首頁：顯示「近 7 天」的名單動態彙整；7 天內都沒有則顯示「近 7 天無台日韓球員動態。」保留區塊讓讀者知道有這個功能。（2026-11-26 調整：首頁近 7 天無內容改為整區隱藏）
- 名單讀取失敗：兩處都不顯示。

## 5. 資料保存與週報介面

metadata 每日一筆新增欄位 `spotlight`（只在有內容時寫入）：

```json
"spotlight": [
  {"player_id": 678906, "kind": "transaction", "text": "<description_zh 或英文原文>", "date": "2026-11-17"},
  {"player_id": 660271, "kind": "news", "text": "<title_zh 或英文>", "link": "https://www.mlb.com/news/..."},
  {"player_id": 660271, "kind": "game", "batting": "4 打數 2 安打…", "pitching": null}
]
```

- 首頁的「近 7 天」由 metadata 讀出，不重打 API。
- 週報（功能 4）可直接讀 metadata 的 `spotlight`，並用 `players_in_transaction`／`players_in_text` 標註其他資料。
- 存的是渲染前的純文字，渲染時才 `esc()`。

## 6. 測試（fixture，不連網）

- 新 fixture：`watchlist_test.json`、含名單球員的原始異動（含小聯盟異動與多人交易）、含名單球員名字的 RSS（標題命中、摘要命中、誤判案例如 "Leeway"）、含名單球員打擊與投球的 boxscore。
- 測試項目：讀檔失敗回空名單；異動比對含 `persons`；新聞整詞比對；boxscore 打擊／投球／二刀流／未出賽；戰報無內容時無區塊；有內容時插槽被填入；首頁 7 天彙整與空狀態；metadata 寫入；XSS escape；匯入規則防護測試仍通過。
- **賽季中的 boxscore 成績只能用 fixture 測試，待 2027 年開季用真實資料驗證**（記入 `docs/progress.md` 待辦）。

## 7. 本機驗證

用休賽季日期（例如 `python fetch_mlb.py --date 2026-11-17 --no-notify`，無 Gemini 金鑰）產出戰報，確認專區內容與名單球員當日真實異動／新聞一致；若當天剛好沒有動態，改找有名單球員異動的日期驗證。
