## 一、目標與原則

- `fetch_mlb.py`（2661 行）拆成 `mlb_daily/` 套件下的多個模組，方便之後加入台日韓球員專區、每週總整理、數據排行榜、季後賽對戰樹。
- **只搬程式碼，行為完全不變**：不改邏輯、不改輸出、不改函式簽章、不加新功能。
- `python fetch_mlb.py ...` 的 CLI 入口與所有參數（`--date`、`--check-wait`、`--max-wait-checks`、`--rosters`、`--no-notify`、`--notify-only`）不變。
- 所有路徑維持 **cwd 相對**（`templates/`、`reports/`、`index.html`、`data/teams/`），不改成 `__file__`，否則測試的 chdir 機制與 workflow 行為會改變。
- 仍只用標準函式庫。

## 三、測試 patch 路徑與呼叫規則

`mock.patch` 只會替換「被 patch 的那個命名空間」裡的名稱。拆分後若仍 patch `fetch_mlb.fetch_json`，子模組呼叫的是自己匯入的名稱，patch 會失效。因此訂定：

1. **跨模組呼叫函式一律用模組屬性**：`from . import net` 後呼叫 `net.fetch_json(...)`，不使用 `from .net import fetch_json`。同模組內直接呼叫照舊。
2. **常數**可以 `from .config import TEAM_META, ...` 直接匯入（不會被 patch，也不會重新賦值）。
3. **狀態 dict**（`LAST_POST`、`LAST_TRANSLATION`、`TX_TRANSLATION_CACHE`）只在定義模組建立一次，其他地方只做原地修改；`fetch_mlb` 重新匯出的是同一物件，測試的 `fetch_mlb.LAST_POST[...] = ...`、`fetch_mlb.TX_TRANSLATION_CACHE.clear()` 照樣有效。
4. **測試修改範圍只限 patch 目標**，改成 patch 定義所在模組，例如：
   - `fetch_json`、`fetch_text`、`post_json` → `mlb_daily.net.*`
   - `get_taipei_now` → `mlb_daily.timeutil.get_taipei_now`
   - `send_discord_notification` → `mlb_daily.notify.*`
   - `top_focus_score` → `mlb_daily.games.*`
   - `fetch_rosters` → `mlb_daily.rosters.*`
   - `build_index_extras` → `mlb_daily.index_page.*`
   - `fetch_standings`／`fetch_countdown`／`fetch_weekly_transactions` → 各自定義模組
   - `fetch_mlb.datetime`（FakeDatetime）→ 實際使用 `datetime` 的那個模組
   - `fetch_mlb.time.sleep`、`fetch_mlb.os.replace`、`urllib.request.urlopen`、`sys.argv`、`os.environ` 本來就是全域 patch，不必改。
   - 測試中直接呼叫的函式（`fetch_mlb.generate_report(...)` 等）與斷言內容不改，靠 `fetch_mlb` 重新匯出。
