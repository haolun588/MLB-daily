# 開發日誌：2026-11-25 延遲排程防護與 favicon 補部署

## 📝 修改摘要

兩個相關問題：一是 GitHub schedule 備援排程被延遲到台北凌晨才執行，導致提前產出尚未就緒的戰報；二是 favicon 因推送時間晚於當日部署，線上一度為 404。前者以 workflow 防護修正（commit `3daebb9`），後者以手動部署補上。

## 🛠️ 詳細改動內容

### 問題一：延遲的備援排程提前產報

- **現象**：備援排程（`cron: '30 6 * * *'`，台北 14:30）被 GitHub 延遲約 11.5 小時，實際於台北 2026-11-25 02:09 執行。
- **原因**：`check` job 以 `TZ=Asia/Taipei date -d yesterday` 計算日期，跨過台北午夜後算成 11/24；當時 11/24 戰報尚不存在，因此提前產報並發送 Discord 通知。
- **修正（`3daebb9`）**：`.github/workflows/daily_report.yml` 的 `check` step 新增防護，`GITHUB_EVENT_NAME=schedule` 且台北小時 < 13 時 `skip=true`；`workflow_dispatch`（cron-job.org 台北 13:00 主排程）不受影響。
- **測試**：新增 `tests/test_workflow_schedule_guard.py`（3 個測試，檢查 workflow 內容與順序）。

### 問題二：favicon 未上線

- **現象**：favicon commit `7908007` 於 02:22 push，晚於 02:09 的部署；13:00 主排程因 11/24 戰報已存在而由 `check` 跳過，未重新部署，線上 `assets/favicon.svg` 為 404。
- **處理**：手動 `workflow_dispatch`（`date=2026-11-24`、`notify=false`）重新部署，run 成功。
- **提醒**：瀏覽器 favicon 快取需 Ctrl+F5 才會更新。

### 文件同步

`docs/progress.md` 新增階段二十四；`docs/architecture.md`、`docs/dev_rules.md` 的排程說明補上「`schedule` 事件於台北 13 點前跳過」。
