# 開發日誌：2026-11-24 網站檔案集中到 site/ 資料夾

## 📝 修改摘要

主資料夾混著網站頁面（`archive.html`、`teams.html`）與本機產生檔（`index.html`、`leaders.html`、`playoffs.html`），使用者希望整理。不能只把 HTML 搬進子資料夾，因為 GitHub Pages 以 gh-pages 根目錄提供網站，網址與相對路徑會壞。方案是新增 `site/` 作為網站發佈根目錄，gh-pages 布局與線上網址不變。對應 commit：`114271f`「refactor: 網站檔案集中到 site/ 資料夾，部署改以 site/ 為根目錄」。

## 🛠️ 詳細改動內容

- **檔案搬移**：以 `git mv` 將 `archive.html`、`teams.html`、`assets/` 移到 `site/`。
- **`mlb_daily/config.py`**：新增 `SITE_DIR`、`REPORTS_DIR`、`METADATA_PATH`、`INDEX_PAGE_PATH`；`FEED_CACHE_PATH`、`SEASON_CACHE_PATH`、`ROSTER_DIR`、`DYNAMIC_WATCHLIST_PATH`、`DAILY_SNAPSHOT_DIR`、`WEEKLY_DIR`、`LEADERS_PATH`、`LEADERS_PAGE_PATH`、`PLAYOFFS_PATH`、`PLAYOFFS_PAGE_PATH` 改由 `SITE_DIR` 組出；`templates/`、`settings/` 不動。
- **寫死路徑改用常數**：`storage.py`、`backfill.py`、`index_page.py`、`cli.py` 原本寫死的 `reports/metadata.json`、`index.html` 等改用常數；`fetch_mlb.py` 補重新匯出。
- **首頁小卡連結**：`leaders.py`、`playoffs.py` 改用 `os.path.basename(...)`，避免 href 變成 `site/leaders.html`（實作中發現的坑）。
- **workflow**：本機還原路徑改到 `site/`（遠端 `origin/gh-pages:...` 不變）、`tar -x -C site`、`stamp_assets site`、`publish_dir: ./site`、移除 `exclude_assets`（只發佈 `site/`，`site/` 內不得放 `.gitignore`）。
- **`.gitignore`**：改為 `/site/index.html`、`/site/leaders.html`、`/site/playoffs.html`、`/site/reports/`、`/site/data/`；`.claude/launch.json` 的 site 預覽加 `--directory site`。
- **測試**：12 個既有測試檔更新路徑與 workflow／gitignore 字串斷言；新增 `tests/test_site_layout.py`（13 個測試）。
- **文件**：`README.md`、`docs/architecture.md`、`docs/dev_rules.md` 已同步路徑敘述。
